# 일괄 처리 + 긴급도 대시보드 설계

## 목적과 이유

교대 시점에는 메모가 여러 건 쌓인다. 지금 앱은 한 건씩 불러와 생성해야 하므로, 다음 근무자가 **무엇부터 봐야 하는지** 한눈에 알기 어렵다. 폴더의 메모를 한 번에 처리하고, 결과를 **긴급도 순으로 정렬한 대시보드**로 보여준다.

## 사용자가 정한 것

- 메모 폴더를 한 번에 처리한다.
- 처리된 건을 한눈에 보는 대시보드가 있다. 긴급 건을 우선 표시한다.
- **긴급도는 메모 내용을 보고 LLM(Claude API)이 판단한다.** 규칙 기반 키워드 판정은 쓰지 않는다.

## 목표

1. 앱에서 폴더(기본 `참고/`)를 골라 그 안의 `.txt` 메모를 한 번에 처리한다. 진행률과 건별 상태(대기/처리 중/완료/실패)를 보여준다.
2. 보고서 생성 호출 한 번에서 Claude가 **긴급도(긴급/주의/일반)와 판단 이유 한 줄**을 함께 돌려준다. API를 추가로 호출하지 않는다.
3. 대시보드에서 다음을 보여준다.
   - 요약 숫자: 전체, 긴급, 주의, 일반, 점검 경고가 있는 건, 실패
   - 목록: 긴급 → 주의 → 일반 순, 같은 등급 안에서는 최근 처리 순. 각 행에 긴급도 배지, 메모 이름, 핵심 내용 한 줄, 판단 이유, 미확인 건수, 경고 건수
   - 행을 선택하면 기존 보고서 카드 화면으로 상세 내용을 본다.
4. 대시보드는 앱을 다시 켜도 이전 처리 결과를 보여준다.
5. 텍스트 보고서에도 긴급도와 이유를 표시한다.

## 비목표

- 긴급도 수동 변경, 담당자 배정, 알림 발송
- 메모 폴더 자동 감시 (사용자가 버튼을 눌러 처리)
- 여러 메모를 묶은 통합 보고서

## 안티 목표

- 메모에 없는 위험을 지어내 긴급으로 올리는 것 (이유는 메모 내용에 근거해야 함)
- 일괄 처리 중 한 건 실패로 전체가 멈추는 것
- 처리 중 화면이 멈추는 것

## 긴급도 판단 기준 (지시문에 넣을 기준 — Claude의 판단, 검토 대상)

- **긴급:** 다음 근무자가 교대 직후 바로 조치해야 함. 예: 안전 위험, 설비 정지·이상이 해결되지 않은 상태, 불량이 퍼질 우려
- **주의:** 교대 근무 중 확인이 필요함. 예: 품질 판정·서류·회신 대기, 출하·납품·수량에 영향
- **일반:** 마감되었거나 기록용으로, 급한 확인이 없음

## Claude의 판단 (검토해 주세요)

- **결과 저장:** 보고서 `.txt` 옆에 같은 이름의 `.json` 파일(보고서 구조, 긴급도, 경고, 원문 이름, 메모 내용 해시)을 저장한다. 대시보드는 `reports/`의 `.json`을 읽어 만든다. 이전에 만든 `.txt`만 있는 보고서는 긴급도가 없으므로 대시보드에 나오지 않는다.
- **중복 처리 방지:** 같은 내용의 메모가 이미 처리돼 있으면 일괄 처리에서 건너뛴다. 기본으로 켜 두고 체크박스로 끌 수 있다. 비용과 중복 행을 줄이기 위해서다.
- **대시보드 중복 정리:** 같은 메모 이름은 최신 결과 하나만 보여준다.
- **동시 처리:** 최대 4건을 함께 처리한다. 순서대로 20건을 처리하면 약 5분이 걸리기 때문이다.
- **화면 구성:** 상단 바에 `메모 작성 | 대시보드` 전환 탭을 둔다. 일괄 처리는 대시보드 화면에서 실행한다.
- **CLI:** `--dir`로 처리할 때도 `.json`을 함께 저장하고, 마지막에 긴급도별 건수를 출력한다.

## 보고서 상세화 (사용자 요청: "각 건 보고서를 지금보다 조금 더 상세히")

원칙은 그대로다: **메모에 적힌 내용만** 쓰고, 모든 항목에 원문 근거 문장을 붙여 자동 점검 대상으로 둔다. 추가 항목(무엇을 추가할지는 Claude의 판단):

- **한 줄 요약:** 다음 근무자가 가장 먼저 읽을 핵심 한 문장
- **시간순 경과:** 메모에 시각이 적힌 기록만 시간 순서로 (시각 표기는 원문 그대로, "오후" 같은 표현도 그대로)
- **주요 수치·대상:** 설비·라인·주문·LOT·제품명과 수량을 원문 표기 그대로 (예: "대기 제품 수량 — 12개")
- **연락·요청 현황:** 누구에게 무엇을 요청했고 회신 상태가 어떤지 (예: "설비팀 — 점검 요청 — 결과 미회신")
- **긴급도와 판단 이유** (위 항목)

텍스트 보고서와 앱 화면 모두 이 순서로 보여준다: 긴급도 → 한 줄 요약 → 발생한 일 → 조치한 내용 → 현재 상태 → 다음 근무자 확인 사항 → 시간순 경과 → 주요 수치·대상 → 연락·요청 현황 → 미확인 사항.
